# Bounded decoded neighbourhood frames

`VideoSessionPool.warmNeighbourhood` accepts at most seven already-authorized source loaders. WatchRSS supplies next 1, previous 1, next 2, previous 2, next 3, next 4, next 5. Far queue previews never load a feed page or request item detail. Navigation, selection, retirement and release cancel pending neighbourhood work. A generation check after asynchronous eviction prevents stale work from starting after foreground navigation.

The Android session `prepare` option `keyframeOnly: true` decodes frame zero with paused Media3 playback and disabled audio selection. It uses the same prefix-cache data source as live playback. The callback resolves after the pixels are cached **and** the decoder lease is released. A cache hit needs no new decoder. Normal live prewarms also cache frame zero.

`PodVideoKeyframes` owns an eight-entry, source/header/geometry-bound LRU. Frames contain real decoder output; posters and saved historical JPEGs never enter this cache. `PixelCopy` copies the video crop into bounded RGBA pixels, and HWUI uploads them with `Bitmap.prepareToDraw`. Readbacks are serialized. TextureView readback on the emulator included codec stride padding; the explicit PixelCopy source rectangle avoids that uninitialized edge. See [PixelCopy's Surface/Rect contract](https://developer.android.com/reference/android/view/PixelCopy#request(android.view.Surface,%20android.graphics.Rect,%20android.graphics.Bitmap,%20android.view.PixelCopy.OnPixelCopyFinishedListener,%20android.os.Handler)).

The maximum persistent pixel allocation is 8 × 466 × 466 × 4 = 6,948,992 bytes (6.63 MiB). Up to another 6.63 MiB holds HWUI texture copies, plus one 868,624-byte (0.83 MiB) readback scratch. Non-square videos use fewer pixels. Cache entries displayed by an ImageView are pinned; trim cannot recycle a displayed frame. Memory pressure drops unpinned frames; service close releases views and cache ownership. Driver allocator retention is not inferred from cache byte counters.

A foreground prepare with a matching cache entry shows that decoded frame before ExoPlayer construction. The first-frame event carries `hasCachedFirstFrame`, separate from `hasRenderedFirstFrame`. The guest removes its opaque waiting UI for either receipt, but the live recovery deadline remains armed until the live decoder renders. Playback is held at frame zero until the TextureView latches its first frame and a real window commit occurs. Then the cached image is removed and requested playback begins. Pause and seek override that pending autoplay. Frame-copy and view-removal operations run outside TextureView's draw callback.

Neighbourhood work waits for a rendered foreground with at least 1 second of buffer (or a paused foreground), for at most 30 seconds. Native admission independently enforces this condition. A foreground buffering event cancels a pending keyframe worker. Only this local foreground-busy/cancel condition is retried; CDN or authorization failures terminate that pass. Immediate standbys are restored first after serial keyframe extraction; additional live standbys are retained if codec and memory limits permit. Low memory can reduce this number. No number of advertised codec instances overrides the shared lease or memory budget.

`MediaCodecList` and the selected codec's `getMaxSupportedInstances()` are upper bounds, not proof of stability. The new DYHIT base preserves the measured watch limit of three live decoders after a five-slot HEVC trial failed. DYFRAME keeps that ceiling on physical devices and unvalidated profiles. The tested ranchu emulator with `c2.android.avc.decoder`, AVC and dimensions up to 240x240 may admit eight sessions, still bounded by codec, runtime correction and memory. Other profiles remain bounded by three. The actual initialized codec name is inspected as well. Native capabilities expose decoder name, advertised instances, admitted limit, current/peak leases, and keyframe entry/byte counts. Player-error telemetry and its collector accept decoder/slot counts only in 0..8. STREAM_MUSIC remains the only mute/volume source.

Validation is separate at each layer: Bun pool/queue/component regressions; Android unit tests for budgets, source binding, worker release and bounded telemetry; a slow-CDN Media3 instrumentation test on emulator 5558 for pixels, window-commit timing, memory and decoder concurrency; and a production VideoPlayerScreen fixture. No emulator number is watch acceptance or mixer/PCM proof.
