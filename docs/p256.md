# Optional P-256 signing and agreement

Import only where signing or ECDH is required:

```ts
import {createP256,validateP256PublicKey} from '@podjs/framework/p256';
const p256=createP256({random:hostRandomBytes,sha256:hostSha256Bytes});
const pair=await p256.generateKeyPair();
try {
  const spki=pair.publicKeySpki;           // copied 91-byte DER SPKI
  const signature=await pair.sign(message); // SHA256withECDSA, raw 64-byte r||s
  const secret=pair.deriveSecret(peerSpki);  // 32-byte raw ECDH X coordinate
  try { /* feed secret to the application's existing HKDF port */ }
  finally {secret.fill(0);}
} finally {pair.dispose();}
```

`P256Ports.random(n)` must return exactly n bytes from a host CSPRNG.
`P256Ports.sha256(bytes)` must return a raw 32-byte SHA-256 digest.
`validateP256PublicKey(spki)` checks the P-256 DER prefix and validates the
uncompressed point. Wrong curves, infinity, invalid points and malformed DER fail.
No private key is exported or persisted. Key generation rejection-samples scalars.
Signing uses low-S signatures and RFC6979 hedged with 32 fresh CSPRNG bytes.
Disposal is idempotent, wipes the private scalar and fences in-flight signing
across both async host boundaries. Private-key operations after disposal fail.
The caller must wipe each returned ECDH secret when finished.

There is no import-time IO or dependency on browser WebCrypto/TextEncoder.
The pure JS implementation is an explicitly imported, vendored noble dependency.
Keep it out of worker/headless bundles. Native verification remains available at
`createCrypto(request).verifyP256` from `@podjs/framework/crypto`; importing that
existing module does not load the optional signing/agreement dependency.

Tests compare generated SPKI, ECDH secrets and ECDSA signatures with independent
Node crypto, and cover malformed inputs, key disposal and cancellation boundaries.
This module adds no native method, platform capability or ABI change.
