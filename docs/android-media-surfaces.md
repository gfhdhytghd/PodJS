# Android scene media surfaces

`MediaSurface` from `@podjs/framework/media-surface` binds a local image or muted video to an owned scene texture. It participates in scene clipping, transforms and stacking. It requires the matching native runtime; image surfaces require `data.images`, video surfaces require `media.video`.

`mediaSurfaces.open(kind, options)`, `update(kind, id, style)`, `state(kind, id)` and `close(kind, id)` expose the native service. The caller supplies an owner ID before opening. Open specifies integer physical dimensions (1–1024), a private relative file path, an optional video poster path and the complete style. Image paths may be omitted for a color/overlay plane. Paths resolve below `files/podjs/files`; absolute paths, traversal and escaping symlinks are rejected. The host permits at most eight surfaces.

Style includes crop/fit/fill, zoom, focus coordinates, rotation, blur in physical pixels, brightness, saturation, base/overlay ARGB and overlay opacity, speed, looping and active state. Update replaces the style; the component always sends the complete style. Appearance updates retain the owner, texture and player. Changing source identity, revision, dimensions or texture sampling reopens. Close is idempotent; queued late decodes recycle their output and cannot resurrect an owner. The Solid binding serializes and coalesces updates and closes its known ID on disposal even if open has not replied.

`textureSampling` accepts `"nearest"` or `"linear"` when opening a surface. Omission keeps nearest sampling and leaves existing request payloads unchanged. This creation-only option controls sampling of the resulting scene texture during scaling and transforms; it does not change Android's bitmap composition, blur or color filtering. It is separate from `MediaSurfaceStyle`: pass it directly to `mediaSurfaces.open`, `bindMediaSurface` or the `MediaSurface` component, never inside `style`. An owner keeps its sampling mode for its lifetime. Native update requests containing this field are rejected with `immutable_textureSampling`, including requests that repeat the current mode. Changing the component's `textureSampling` prop closes the old owner and opens a new one. Existing background and other consumers retain nearest sampling unless they opt in.

Current hosts report the effective mode in `MediaSurfaceState.textureSampling`. That state field is optional so older host replies remain readable. For an explicit `"linear"` request, the binding requires the open reply to confirm `"linear"` before attaching the texture to the scene. A host that omits the field or reports another mode causes the binding to close its own session and report an error through `onError`; the component keeps its fallback. Callers using the lower-level `mediaSurfaces` service directly must check this readback themselves. Omitted or explicit `"nearest"` requests remain compatible with older hosts that omit the state field.

`style.presentationFrame` is an optional, mutable presentation transform inside the fixed output viewport established by the open request's `widthPx` and `heightPx`. Its object requires all six numeric fields: `{leftPx, topPx, widthPx, heightPx, scale, opacity}`. All values must be finite. Frame width and height are positive integers at most 1024; scale is in `[0.25, 8]`, opacity in `[0, 1]`, and left/top in `[-32768, 32768]`. Coordinates are physical pixels relative to the output viewport. Negative or fractional positions and frames extending beyond the viewport are allowed; the output clips them. The host applies the transform natively. Frame changes travel with the complete style in one update and retain the surface owner and fixed output dimensions rather than reopening the surface.

Update replaces the complete style, including `presentationFrame`. Omitting that field resets presentation to the existing default; the request does not inject a frame or a `null` value. `MediaSurfaceState.presentationFrame` reports the normalized effective frame, or `null` when presentation is omitted. The field is optional for compatibility with older hosts. For an explicit frame, the binding checks acknowledgement against the snapshot actually sent on open and on every update, accounting for native numeric normalization. A missing or mismatched acknowledgement is an unsupported presentation request: the binding closes its owned session, reports the error and leaves the component fallback visible. A reset accepts either `null` or an omitted state field. Direct service callers receive the raw host readback and must validate it themselves.

Presentation changes only the native placement, scale and opacity. It preserves the existing brightness, blur, base-color and overlay effect order, including the API 30 blur fallback described below.

`brightnessBias` is an additive RGB offset in the normalized range `[-1, 1]`, with a default of `0`. The color matrix first applies the existing brightness multiplier and saturation transform, then adds `255 * brightnessBias` to each RGB channel; it leaves alpha unchanged. Channel values are clamped by Android's color-filter pipeline. For example, `brightness: 0.7, brightnessBias: 0.3, saturation: 1` maps opaque black to 30% gray and preserves white. These parameters do not change the separate base color or overlay plane. Non-numeric, non-finite and out-of-range bias values are rejected.

`blurEdgeMode` accepts `"decal"` (the default) or `"clamp"`. On API 31+, these select the corresponding Android `Shader.TileMode` for `RenderEffect`: decal samples transparency outside the image plane, while clamp extends the plane's edge colors. Both remain clipped to the surface rectangle. The color matrix is drawn into the plane before this blur, and the existing base/overlay composition remains outside it. Updating blur radius or edge mode reuses the decoded bitmap on API 31+; it does not reopen or decode the source file. Other values and non-string modes are rejected. Omitting both new fields preserves the previous appearance.

Android renders a native hardware plane at actual viewport dimensions into an owned power-of-two RGBA texture. Stable texture updates advance the engine revision and redraw; guest JavaScript receives no per-frame pixel data and no RGBA files are created. Video uses an independent ExoPlayer with volume zero and no audio-focus request, captures frames from a private noninteractive TextureView, and pauses on inactive/background lifecycle. Errors retain the poster or base. The state exposes frame count, position, owner and player generation; a naturally ended player currently reports paused.

API 30 images use intrinsic RenderScript blur; video uses Media3 GaussianBlur with downsampling. Those existing paths and their edge handling are unchanged: `blurEdgeMode` selects only the API 31+ RenderEffect mode. API 30 image blur is baked before the existing paint color matrix, so its effect order differs from API 31+. Consumers matching a reference that disables blur below API 31 must pass `blurPx: 0` on those devices. A blur-radius change on API 30 still reloads the original image before applying intrinsic blur. Decode is limited to 64 megapixels and 16384 pixels per axis, with sampling for large sources. EXIF orientation is not yet applied. The watch evidence covers small PNG images, H264 video, state/lifecycle and failure fallback. Large-image sampling parity, EXIF, HDR, video-effect pixel equivalence, API 31+ rendering, sustained frame cost and power remain unverified.

Application-level reference captures cover native geometry/color/blur comparisons, full 466-square Compose image comparisons, playback continuity and disposal. These bounded checks do not establish all-device acceptance or verify the new bias/edge-mode combinations and animated API 31+ updates. Those require runtime rendering and frame-cost checks in addition to parameter and ownership regressions.

The eight applicable `PodMediaSurfaceStyleTest` checks passed on API 30, including actual Android Canvas color-filter output for positive/negative bias, alpha preservation, endpoints and the existing saturation/gain combination. The ninth test, decoded-image reuse during API 31+ blur updates, was skipped by its API assumption. Canvas filter results do not establish animated native-surface GPU parity; that boundary remains open.

Host diagnostics can optionally install the package-private `PodMediaSurfaceServices.TimingObserver` with `setTimingObserver` on the main thread. The setter returns the previous observer so a bounded measurement can restore it in `finally`. The default is `null`: no diagnostic clock reads or timing arrays are created until observation is enabled. This is a Java host diagnostic hook, not a guest service, media style field or rendering mode.

Each `record(sessionId, kind, values)` call runs synchronously on main and lends the observer a reusable `long[Timing.FIELD_COUNT]`; its contents must be copied before returning. A collector should preallocate fixed-capacity primitive storage, count overflow, and serialize only after measurement. The service does not create a record object, JSON or log entry per sample. Observer exceptions, including assertion errors, are contained. Observers must not reenter rendering, mutate the borrowed array or perform blocking work. Restoring or replacing an observer suppresses queued dispatch samples belonging to the previous observer.

`Timing.DISPATCH` and `Timing.RENDER` have independent increasing `SEQUENCE` values. Render records carry `DISPATCH_SEQUENCE`, cause, texture handles before/after, image-load revision, actual viewport dimensions and power-of-two texture dimensions. Initial and style renders refer to their open/update dispatch. An asynchronous decode refers to the dispatch that started that load; zero means no observed initiating dispatch. Video frame/state causes remain separate. The revision is the existing load-generation counter, not proof that a new bitmap was decoded during that render.

Dispatch records separate enqueue, main-thread execution, work completion, synchronous success/failure callback calls and final return. The callback interval measures only that Java callback invocation; it does not establish when a later host event, JavaScript Promise continuation or scene frame ran. Render records separate RenderNode recording, `syncAndDraw`, image acquire plus hardware-buffer wrapping, `hardware.copy`, `getPixels`, resource cleanup and `TextureSink.write`. All timestamps use `System.nanoTime()` and represent CPU wall time, including waits and scheduling. They do not report pure GPU execution time, buffer latch time or physical display time. In particular, the draw request's existing `setWaitForPresent(true)` does not turn this diagnostic into a display-present probe.

Zero timestamps mark stages that were not reached. Attempted stages retain end timestamps even when they throw; `OUTCOME` and `FAILED_STAGE` distinguish exceptions from a rejected sink handle and successful completion. On a failed acquire/wrap, its end marker can include cleanup of a partially acquired resource. A failed copy or pixel read retains its stage while normal `finally` cleanup is recorded. Existing exception handling and service error messages remain unchanged. The render sample ends before observer delivery; dispatch work can include that observer's cost, so enabled measurements still require overhead calibration and do not establish zero-cost instrumentation. `PodMediaSurfaceTimingTest` exercises these contracts; its source alone is not evidence of device execution.
