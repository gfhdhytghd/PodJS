# Decoded video swaps

`VideoSessionPool.prepare` adopts an identically authorized neighbour without reopening media, seeking, flushing, reconnecting its surface, or waiting for diagnostic state/loop round trips. `video.session.promote` accepts `loop` and returns `replacedHasRenderedFirstFrame` atomically. Older hosts retain the state/loop fallback. A changed loop during promotion still synchronizes before completion.

A prewarm draws its TextureView underneath the opaque foreground page. Preparation completes only after both Media3's decoded-first-frame notification and TextureView's surface update. Child reordering preserves player, surface, layout, and source generation. Promotion pauses the outgoing player and disables its audio selection before revealing the incoming page. This is player-state evidence, not mixer/PCM silence evidence.

The guest can acknowledge cover removal during the release callback when it keeps the decoded page uncovered. Native code independently checks the target, source generation, decoded/latched state, bounds, focus, and visibility. For a retained latched texture, `incoming_first_frame` is the first real hardware window commit after promotion and acknowledgement. It does not force an unrelated PodRuntimeView redraw. A fresh surface still requires two UI window commits. Cancellation invalidates the observer. A timeout never counts as a frame.

`DYBENCH code=swap_stage` is native-only. Closed stage values are `promote_enter`, `surface_promoted`, `play_command`, `texture_updated`, `rendered_first_frame`, `ui_confirm`, `observer_armed`, `window_commit_1`, and `window_commit_2`. All stages carry the action sequence, action generation, native target source generation, and native event-time uptime. PID comes from the log transport. An early UI acknowledgement retains its actual timestamp until native target binding exists. Texture updates after a retained reveal describe subsequent playback; its cached decoded first frame was latched before release.

`visibleDecodedMs` is release-to-`incoming_first_frame` in native uptime, paired by PID, action sequence, and action generation. Immediate intent selection does not include the legacy 96 ms settle animation. Older measurements waited for two window commits and could count an offscreen decoded texture before it updated. They must not be presented as direct physical first-pixel comparisons with the retained-texture metric.
