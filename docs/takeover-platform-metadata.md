# Platform metadata during Android takeover

The business snapshot excludes only `files/profileinstaller_profileWrittenFor_lastUpdateTime.dat` and `files/profileInstalled`. These are reserved ProfileInstaller files, not imported assets. Links and directories under these names are rejected. All other file inventories, hashes, changes, unknown-content blockers and fixed-snapshot checks remain strict. **NativeBackup still preserves both metadata files and uses the unchanged shared recovery protocol.**

The runtime manifest removes automatic `ProfileInstallerInitializer` startup. Successful `PodTakeover` admission schedules the original initializer on the main looper once per sandbox. It retains the library's first-frame callback and 5–6 second background delay. PAUSED or BLOCKED admission does not schedule it. This also supports successful no-source admission. The initializer removal lives in the runtime library so Android watch and Wear hosts inherit it.

## Journal compatibility and digest evidence

The converter version remains `watchrss-room-v18-1+watchrss-stores-3+watchrss-files-3`. Existing PAUSED/stage_failed/DETECTED journals use T13's fresh generation retry. Failed candidates remain retained; two consecutive failed generations are covered. Completed snapshots remain immutable and keep their recorded bytes rather than recapturing mutable sources.

The full four roots and combined manifest retain their original digest encoding and meaning. A separate `files_without_platform_metadata` aggregate uses root-relative paths with only the two exact metadata names removed. It is projected from the snapshot and the sealed NativeBackup manifest; it does not modify that manifest or its seal.

New host receipts use `pod-takeover-digest-v2`. V1 receipts are accepted as historical evidence, but a files/manifest mismatch cannot be attributed strictly to a marker from root aggregates alone. Such a comparison remains `PARTIAL`, `equal=false`, with `nonPlatformFilesVerified=false` and a nonzero verification exit. V2 may return `PASS_WITH_KNOWN_DIFFERENCES`, still `equal=false`, only when databases/shared_prefs/no_backup and the files subset match pre/SNAPSHOTTED/ACTIVE. Missing logs, wrong PID/generation, conflicting aggregates and changes outside that policy remain failures.

Release diagnostics add `code` only for messages matching `[a-z0-9_]{1,64}` and carry an allowlisted file-converter category with the original exception class and stack frame. No path, arbitrary message, cause or Throwable is logged.
